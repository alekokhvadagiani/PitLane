## Shared stationary coordinate filter (2026-10-26)

Investigated the malformed Shanghai trace in OpenF1 Chinese GP Race session 11245. A bounded API probe found the identical coordinate `(-8325, -7058)` repeated 4,820 times across 22 drivers for about 179 seconds. This was stationary provider output, not an actual pit lane or circuit segment, but the frontend had included it in the circuit bounds and connected it to the genuine sampled path. Replay now excludes coordinates shared by at least four drivers, repeated at least three times per driver, across at least five seconds, before fitting geometry and rendering traces/markers. Focused regression tests cover the repeated placeholder and a briefly shared coordinate. This deliberately avoids distance/velocity filtering because OpenF1's location docs do not define coordinate units. No build, test, browser session, or service restart was performed; the user will restart the frontend and verify the result.

## Historical catalog increment (2026-10-26)

## Selected-lap replay increment (2026-10-26)

Added session driver discovery, per-driver lap timing, and a position endpoint capped at three minutes. Replay now plots the selected lap's actual OpenF1 local X/Y trace, reports returned lap/position coverage, shows lap and sector timing on a UTC-normalized event timeline, and supports play, pause, seek, restart, and 0.5×–4× playback. The car marker updates via animation frame and stops at gaps rather than extrapolating. This is selected-lap playback, not a full-session replay, leaderboard, or surveyed circuit map. Build/lint/format checks passed; no service was started for this increment, and browser rendering remains unchecked.

## Unified replay clock and race cockpit (2026-10-26)

Moved playback time, gap-aware position interpolation, telemetry sampling, and label placement into independently testable replay-engine helpers. One `requestAnimationFrame` clock now drives markers, gauges, lap/timeline readouts, and window changes; transient display updates use DOM refs, with React state changes only at data-window/classification boundaries. Position samples are sorted/deduplicated and never interpolated across null coordinates or gaps greater than 1.5 seconds. Speed, RPM, and throttle interpolate at the playhead; gear, brake, and DRS use the last state at or before it. Selecting away cancels obsolete requests. Browser fetches time out after 20 seconds.

Redesigned the circuit as a uniformly fitted, layered SVG road trace with the selected driver's recorded route highlighted in team color. Label placement prioritizes the selected driver, avoids collisions, keeps labels in bounds, and provides an expandable group list when the viewport cannot fit every label. A spinning original tire SVG and staged status strip distinguish loading, partial, ready, empty, and failed data; its 10/25/50/15 weighted percentage measures completed required stages, not downloaded bytes. Historical query data stays fresh for 30 minutes, remains in browser memory for 15 inactive minutes, and uses the existing 30-minute API memory cache. No durable cache or new dependencies were added.

Automated verification: 39 Playwright cases passed across 1920×1080, 1440×900, and 390×844, including six replay-engine cases, loading/error/retry, client cache reuse, request cancellation, and session interactions. Frontend build, lint, and format checks passed. Manual browser verification against running local services used real OpenF1 session 11396: 22 drivers, 15,048 and 15,158 position records in consecutive windows, 667 selected-driver car samples in the later window, synchronized gauges at a 1:30 seek, and 22 in-bounds non-overlapping labels at 1440px. No page errors or horizontal overflow were observed. The .NET backend was unchanged during this milestone. No backend test project exists.

## Tyres and driver status (2026-10-26)

Added cached OpenF1 adapters/endpoints for session-wide laps, tyre stints, pit records, and final session results. The timing tower resolves each driver's compound against their own replay-time lap; fresh position samples show `TRACK`, the recorded pit-stop event is marked briefly at its timestamp, stale positions show `NO DATA`, and published DNF/DNS/DSQ appear as final results and are hidden from the circuit map. Lane duration is shown in the pit-stop log but is not used to infer how long a car remains in the pit lane because the provider does not specify whether the event time marks entry or exit. Final DNF flags are not timestamped. The gauge now uses normalized arc length and updates dash lengths from speed/throttle values, so segments grow from a fixed zero point instead of sliding around the circle. Provider data was directly probed for session 11396: 1,166 laps, 54 stints, 32 pit records, and 22 final results. .NET Release build/format passed; all 51 Playwright tests passed across wide, desktop, and mobile viewports. The new API endpoints compile but require a user-driven API restart and runtime verification. No service was restarted by Codex.

## Circuit stability and missing-session states (2026-10-26)

Used one fixed early-session position window to establish the SVG coordinate transform, then project each replay window through that same transform. This prevents position-window bounds from changing the apparent circuit scale and car paths as the playhead advances. Corrected leader lines to begin at the precise car-marker coordinate and connect to the nearest label edge. Tire compounds can display as `STARTING` or `LAST REPORTED` only when the provider supplies a stint but no matching lap; lap/stint request failures now have visible retry actions. DNS, DNF, and DSQ are shown from final classification with an explicit final-result qualifier; DNS drivers do not show recorded zero/sentinel telemetry as on-track measurements. Added focused regression tests for DNS compound fallback and DNS status priority. Read-only API requests against the running local backend confirmed 2026 Chinese GP Race session 11245 returns 14,916 position samples in a three-minute window, 924 lap rows, 41 stints, and a DNS + one recorded HARD stint (without lap rows) for driver 1. The latest UI/test changes have not been built or run in the browser; the user will run/restart the frontend. No service was started or stopped.
