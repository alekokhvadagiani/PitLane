# Architecture

## Foundation

PitLane is a local-first personal application. A React/Vite SPA calls a same-origin `/api` boundary backed by a .NET 10 minimal API. Vite proxies API requests in development; Nginx does so in Compose. The backend exposes health, truthful capability metadata, and a cached OpenF1 historical meeting/session catalog.

```text
React views ── TanStack Query ── /api ── ASP.NET Core
     │                                    │
shared visualizations             provider interfaces
     │                                    │
session clock                     OpenF1 historical catalog
```

One backend project is sufficient until complexity proves otherwise. No database, message broker, background worker, SignalR hub, or Python service is needed for the shell. No authentication is provided; bind development services to localhost.

## Planned session boundary

Use a provider-qualified session ID, UTC `DateTimeOffset` origin, optional end time, driver identities scoped to a session, and per-stream availability (`available`, `unavailable`, `unknown`, with reasons). Provider DTOs stay inside adapters; normalized models cross the API. A schedule entry is not evidence that replay data exists. Do not join providers on driver number alone.

The replay control deck uses the shared clock's integer milliseconds relative to session UTC. It exposes recorded lap boundaries and pit stops when available; pit-lane entry/exit positions are estimates from `date` and `laneDuration`, not provider-guaranteed timestamps. Each event seeks through the same session clock used by positions and telemetry. Race-control flags and radio markers are omitted until those timestamped streams are integrated. Preserve simultaneous events and distinguish missing data from zero.

`ReplayClock` in `features/replay/replay-engine.ts` is the single session clock: `performance.now()` deltas are multiplied by playback speed and accumulated into session-relative milliseconds. Seek, pause/resume, speed changes, and session teardown all act on that clock. A single `requestAnimationFrame` loop publishes its timestamp to narrow subscribers. Map marker coordinates, telemetry instruments, elapsed time, lap readout, and timeline playhead use the same timestamp. DOM refs update at frame cadence; React state changes only on window and classification boundaries or user actions. Live mode is not implemented; a future live clock will need server alignment and a bounded jitter buffer.

Position and car-data inputs are parsed, sorted, and de-duplicated before rendering. Position interpolation uses binary search and shape-preserving, timestamp-based cubic interpolation only between valid adjacent samples no more than 1.5 seconds apart. It does not overshoot the recorded points. Null coordinates and large time gaps split the trace; no extrapolation crosses them. Continuous telemetry (speed, RPM, throttle) is linearly interpolated across a maximum three-second interval; gear, brake, and DRS retain the latest state at or before the playhead. When a window begins after the session origin, initial playback aligns to the earliest recorded location sample instead of inventing an initial position.

## Provider resilience

`IHistoricalSessionProvider` isolates the OpenF1 adapter from API endpoints. `/api/meetings?year=` accepts years from 2023 through the current UTC year; `/api/meetings/{meetingKey}/sessions` returns session metadata; `/api/sessions/{sessionKey}/weather`, `/drivers`, `/laps?driverNumber=`, `/all-laps`, `/stints`, `/pit-stops`, `/results`, and `/positions?driverNumber=&fromUtc=&toUtc=` expose session data. Position windows are capped at three minutes. Catalog responses carry provider provenance and retrieval time. The adapter uses a 12-second HTTP timeout, propagates request cancellation, normalizes malformed/unavailable upstream responses to 503 Problem Details, and caches session/driver/range queries in memory for 30 minutes. Requests are bounded to one season, meeting, driver, or short interval. The UI also caches queries for 30 minutes and exposes retry controls.

The meeting/session catalog describes events and session timestamps only. Weather is separate timestamped context and does not establish that location, lap timing, telemetry, or radio streams exist. Preserve nullable measurements and gaps; OpenF1 rainfall is a binary reading, not a precipitation amount. Location requests are bounded to three minutes. `/race-positions` returns all drivers' location samples for one bounded window, `/classification` returns timestamped running-order changes, and `/car-data` returns selected-driver telemetry for one bounded window. `/all-laps` and `/stints` let the tower associate each driver's replay-time lap with its compound; when lap timing is absent, only a clearly labeled starting or last-reported compound may be shown. `/pit-stops` exposes event dates and lane durations, but OpenF1 does not specify whether the date marks lane entry or exit. The replay estimates the visit as `[date - laneDuration, date)`, an interpretation consistent with the inspected 2026 Chinese GP Race samples; it is an estimate, not a provider guarantee. Pit-stop rows seek to this estimated entry, the amber marker is active only during the interval, and records without a usable duration do not imply an active visit. `/results` provides final DNF/DNS/DSQ outcomes, not timestamped retirement moments; these are visibly labeled final results, and a final DNF must not be presented as a known retirement time. Hide DNS/DNF/DSQ drivers from the circuit map because there is no reliable retirement timestamp. DNS takes precedence over a recent location sample because the driver did not start. A fresh location sample (up to two seconds old) indicates `ON TRACK`; stale/missing samples show `NO DATA`. Full-session replay advances through position and telemetry windows; it does not fetch all high-frequency samples at once. TanStack Query deduplicates matching active query keys within the browser and caches replay data with 30-minute freshness and 15-minute inactive retention. The API's normalized `IMemoryCache` entries expire after 30 minutes; this is process-local and is not durable or coordinated across API instances. No persistent browser cache is used because the application currently loads bounded windows. Browser fetches combine Query cancellation with a 20-second timeout. Interpolate only between adjacent location samples less than 1.5 seconds apart. The plotted trace derives from provider-local X/Y coordinates and is not surveyed circuit geometry. OpenF1's `404 {"detail":"No results found."}` means that stream has no observations; normalize that specific response to an empty catalog, not a service outage. OpenF1 returned a 429 with a three-requests-per-second message during direct probing; a shared 450ms request gate spaces upstream calls. Treat observed limits as changeable, preserve `Retry-After`, and never replace provider failures or missing streams with synthetic race data.

## Frontend

Shared shell, button/dialog primitives, typed API transport, and URL-addressable Overview, Live, Replay, Telemetry, and Team Radio navigation. TanStack Query owns remote state. Motion is purposeful and honors reduced motion; fonts are bundled locally. Replay uses a compact session-browser dialog and a shared race workspace: timing tower, fitted provider-derived circuit trace, selected-car instrument panel, and replay timeline. A fixed three-minute sample near session start establishes one uniform X/Y projection; active-window car positions use the same transform so the circuit and cars do not rescale as replay advances. If that geometry request is empty or fails, current-window coordinates provide a labeled fallback. Before fitting or drawing paths, replay removes a coordinate only when it is repeated by at least four drivers, at least three times per driver, across five or more seconds; this filters a confirmed OpenF1 stationary placeholder without assuming undocumented coordinate units. Null coordinates and large time gaps still split paths. The traced path is sampled provider data, not surveyed geometry. Road surface and edge are layered SVG strokes, while selected-driver route color and team-colored dots come from provider data. DNS/DNF/DSQ drivers are excluded from moving markers. The initial selection prefers the classified winner with a valid result, then a non-DNS driver; explicit user selection always takes precedence. There are no inferred sectors, DRS zones, or pit geometry. Collision labels are laid out in screen space: selected first, then stable nearby candidate slots. A remembered slot tolerates up to 8px horizontal and 6px vertical intersection before relocating, reducing rapid label hopping in dense packs; leader lines still start at the actual marker coordinate. Drivers without a collision-free label are grouped behind an expandable `+N` marker; none are drawn at the SVG origin. Track markers and telemetry values update through DOM refs on the shared replay clock; React does not update the full marker list per animation frame. Instrument arcs use SVG `pathLength=100`; their dash lengths scale with speed (0–360 km/h) and throttle (0–100%) while their offsets remain fixed at zero, preventing the displayed segment from sliding around the circle. Missing channels hide the corresponding colored arc. A tire-inspired SVG loader reports weighted completed stages (session metadata 10%, drivers 20%, positions 30%, fitted trace 20%, laps and stints 20%); it does not claim byte-level progress, and empty/error stages never reach 100%. Lap/tire provider errors are visible and retryable. A DNS car shows its last-reported compound with that qualifier and suppresses misleading on-track telemetry. Loading, partial, ready, empty, and failed states are separate. Live, telemetry comparison, and radio currently show truthful availability states. The overview artwork is illustrative, not measured geography.

## Design system

Palette: asphalt `#08090c`, panel `#111419`, elevated `#1b2027`, rule `#303640`, text `#f4f5f7`, signal red `#f20d18`. Oxanium carries prominent instruments and timing; Barlow Condensed provides compact motorsport labels; Barlow supports longer UI copy. The replay workspace uses a timing tower, dominant circuit, and selected-car instrument rail, with one integrated scrubber and event layer in a red-accented control deck. Red marks primary action/selection; lap markers are neutral, estimated pit entry is amber, and estimated exit is green. Event clusters retain individual seek targets. Current session UTC, elapsed time, duration, lap and lap time are grouped with a recorded-lap selector, restart, ±10-second seek, play/pause and 0.5×/1×/2×/5×/10× speed controls. Choosing a lap seeks to that driver's provider-recorded lap start through the shared clock; missing lap data is shown as unavailable. The native range input preserves pointer and keyboard seeking. Mobile controls stack without reducing the timeline to a second progress bar.

## Verification

Build and lint both codebases as applicable; browser-check 1920×1080, 1440×900, and mobile layouts, navigation, session dialog, failure states, and keyboard focus. Frontend tests cover clock control, interpolation and data gaps, continuous/discrete telemetry synchronization, label collisions and stability, loading versus empty states, retry, query-cache reuse, and request cancellation. Mocked provider fixtures do not establish upstream coverage. A manual real-session check on 2026 US GP session 11396 verified 22 drivers and two three-minute position windows with 15,048 and 15,158 records; the selected driver returned 667 car-data samples in the next window. A real Chrome run on 2026 Chinese GP Race session 11245 measured four five-second captures at 1×/2×/5×/10×: approximately 60 rendered frames/s at each speed; 1× frame intervals were p50 16.7 ms, p95 17.4 ms, p99 17.6 ms, max 26 ms. At 10×, frame intervals were p95 19.2 ms, p99 26.2 ms, max 28.9 ms while the replay clock advanced about 167 ms per typical frame. Track-map subscriber work stayed below 1.1 ms max; main replay subscriber work stayed below 2.7 ms max. React rendered four times per capture rather than once per frame. Session 11245 position cadence was p50 240 ms, p95 420 ms, p99 481 ms, max 820 ms. Interpolated marker displacement at 1× was p50 0.229, p95 0.533, p99 0.651 map pixels/frame; at 10× it was p50 2.218, p95 5.063, p99 6.610, max 9.452. Label offset changes per capture fell from 36/68/112/178 frames to 9/18/41/64 frames at 1×/2×/5×/10× after placement hysteresis. These are single-machine, headless Chrome measurements, not a guarantee for all devices. Hamilton's pit window also contains about 33 seconds of shared invalid placeholder coordinates; those positions remain unavailable and are not interpolated. The replay control deck was browser-checked at 1920×1080, 1440×900, and 390×844. Its integration test covers a single scrubber, recorded-lap jumps including repeated jumps to the current lap start, event clustering and seek, ±10-second seeking, five speed choices, pointer scrubbing, keyboard seeking, and synchronized telemetry. It also asserts the no-lap-data state. The full Playwright suite passed 78 checks; screenshot: `docs/screenshots/race-control-deck.png`. The backend has no unit-test project.
